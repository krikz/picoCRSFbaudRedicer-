# Настройки

Все параметры задаются через макросы препроцессора. Значения по умолчанию лежат
в `firmware/include/crsf_baud_config.h`, значения таргета — в
`firmware/targets/RP2040_CRSF_BAUD_REDUCER/target_config.h` (подключается первым
и имеет приоритет).

Переопределить можно на уровне сборки:

```bash
pio run -e rp2040_crsf_baud_reducer \
  -D CRSF_BAUD_IN=420000UL -D CRSF_BAUD_OUT=230400UL
```

или в `platformio.ini`:

```ini
[env:rp2040_crsf_baud_reducer]
build_flags =
    ${env:rp2040_crsf_baud_reducer.build_flags}
    -D CRSF_BAUD_IN=420000UL
```

## Скорости

| Параметр | Умолчание | Смысл |
| --- | --- | --- |
| `CRSF_BAUD_IN` | `420000` | скорость от приёмника. 420000 — ExpressLRS (как в biba), 400000 — базовый CRSF/TBS Rev7, 416666 — CRSF Rev10 |
| `CRSF_BAUD_OUT` | `230400` | скорость в полётник: **ровно та**, что выставлена на полётнике. Стандартные CRSF-скорости: 400000 / 416666 / 420000; из обычных UART — 115200 / 230400 / 460800 / 921600 |

## UART и пины

| Параметр | Умолчание | Смысл |
| --- | --- | --- |
| `CRSF_BAUD_IN_UART` | `2` | UART на входе: 1 = Serial1 (UART0), 2 = Serial2 (UART1) |
| `CRSF_BAUD_OUT_UART` | `1` | UART на выходе |
| `CRSF_BAUD_IN_RX_PIN` | `9` | GP9 — приём CRSF от приёмника |
| `CRSF_BAUD_IN_TX_PIN` | `8` | GP8 — передача в приёмник (обратный канал) |
| `CRSF_BAUD_OUT_TX_PIN` | `4` | GP4 — передача CRSF в полётник |
| `CRSF_BAUD_OUT_RX_PIN` | `5` | GP5 — приём CRSF от полётника (обратный канал) |
| `CRSF_BAUD_ECHO_ENABLE` | `0` | обратный канал полётник → приёмник |

Два UART должны быть разными — иначе сборка падает с ошибкой.

## Буфер и таймауты

| Параметр | Умолчание | Смысл |
| --- | --- | --- |
| `CRSF_BAUD_QUEUE_SLOTS` | `8` | сколько целых кадров в очереди (слот = 64 байта) |
| `CRSF_BAUD_COALESCE` | `1` | прореживание: новый кадр заменяет более старый кадр того же типа |
| `CRSF_BAUD_FRAME_TIMEOUT_MS` | `20` | таймаут неполного кадра, мс |
| `CRSF_BAUD_RX_CHUNK` | `64` | сколько байт забирать из приёмника за один проход |

## Логи и индикация

| Параметр | Умолчание | Смысл |
| --- | --- | --- |
| `CRSF_BAUD_LOG_BAUD` | `115200` | скорость USB-консоли |
| `CRSF_BAUD_LOG_EVERY_FRAMES` | `100` | как часто печатать статистику; 0 = не печатать |
| `CRSF_BAUD_LED_ENABLE` | `1` | мигание светодиода при приёме |
| `CRSF_BAUD_LED_PIN` | `25` | GP25 |

## Подбор скоростей на лету

Скорости меняются из USB-консоли без пересборки:

```
baud_in  420000      новая скорость приёмника
baud_out 230400      новая скорость полётника
status               текущие значения (запрошенная и фактическая скорость UART)
stats                счётчики
help                 список команд
```

В `status` видно и **фактическую** скорость UART: делитель у RP2040 дробный, и если
расхождение с запрошенной больше 3 %, выводится предупреждение — это признак того,
что запрошенную скорость UART не смог выставить точно.

## Статистика в логах

```
crsf: ok=1234 bad=0 dropped=0 in=29576 out=29576 q=0/32
```

- `ok` — принято валидных кадров;
- `bad` — отброшено (битый CRC или недопустимая длина);
- `dropped` — вытеснено из очереди (вход быстрее выхода);
- `coalesced` — заменено более свежим кадром того же типа;
- `in`/`out` — байты принято/отдано;
- `q` — занято слотов из доступных.


## Буфер приёма UART и неблокирующая печать

Два параметра появились из-за вскрытых причин, а не «на всякий случай»:

### `CRSF_BAUD_RX_FIFO_SIZE` (по умолчанию 256)

В ядре Arduino-Pico FIFO приёма UART — **32 байта**. На 420 кбод это
всего ~760 мкс запаса. Отправка кадра в полётник блокирующая
(`uart_write_blocking`), и всё это время мост не читает вход ⇒ FIFO
переполняется ⇒ байты теряются молча, а полётник получает битый кадр.

256 байт = ~6 мс запаса на 420 кбод. Менять только **до** `begin()`
(ядро запрещает менять размер у запущенного UART) — прошивка делает это
автоматически, в том числе при смене скорости на лету.

Если в статистике растёт `uart_ovf` — увеличь буфер или ускорь выход.

### Неблокирующая печать в USB-консоль

Буфер USB-CDC — **64 байта**, а строка статистики длиннее. `Serial.printf`
в этом случае **блокируется**, пока хост не прочитает данные (до секунды),
и всё это время конвейер не читает CRSF.

Поэтому текст идёт через очередь `crsf_baud_log` (переносимый модуль с
нативными тестами), а наружу отдаётся порциями по мере освобождения места
в буфере CDC. Никогда не блокирует.

Если очередь лога переполнилась (хост не читает), вытесняется самая
старая строка — свежие данные важнее. Счётчик: `overwritten`.
